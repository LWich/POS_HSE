# ПОС — преподавательская оценка студентов

Модуль одного курса на Python 3.12. Через REST API и консоль можно вести список студентов и рубрикатор, выставлять, исправлять и отменять оценки, рассчитывать итоги, смотреть аналитику и выгружать ведомость в CSV.

## Запуск в Docker

Настройки запуска хранятся в `.env`. Если файла нет, создайте его командой `cp .env.example .env`. Переменные окружения имеют приоритет над значениями из файла.

Соберите и запустите контейнер из каталога проекта.

```sh
docker compose up -d --build --wait api
```

Откройте [Swagger UI](http://127.0.0.1:8000/docs). `POS_BIND_HOST` и `POS_PORT` задают адрес и порт публикации на компьютере. `POS_DOCKER_API_HOST` и `POS_API_PORT` задают адрес и порт сервера внутри контейнера. В установках с отдельной командой Compose используется `docker-compose`.

API и CLI читают `POS_DB_PATH` и `POS_DB_TIMEOUT` через `pydantic-settings`. По умолчанию данные хранятся в общей SQLite-базе `/data/pos.sqlite3` на томе `pos-data`. Обычный `docker compose down` сохраняет том. Существующая база открывается через SQLAlchemy с той же схемой.

Для запуска без Docker установите зависимости из `requirements.txt`, задайте доступный для записи путь к базе, например `POS_DB_PATH=./pos.sqlite3`, и выполните `python -m pos.adapters.api` из каталога проекта. Адрес задаёт `POS_API_HOST`, по умолчанию сервер слушает `127.0.0.1`.

## Демонстрация в консоли

```sh
docker compose exec -T api python -m pos.adapters.cli demo
```

Команда использует временную базу. Она добавляет двух студентов и два критерия, выставляет оценки, выводит итоги **7.70/10** и **4.00/10**, затем печатает CSV.

Следующие команды работают с общей базой.

```sh
docker compose exec -T api python -m pos.adapters.cli --help
docker compose exec -T api python -m pos.adapters.cli students add "Анна Волкова"
docker compose exec -T api python -m pos.adapters.cli criteria add "Проект" 20 60
docker compose exec -T api python -m pos.adapters.cli grades add --help
docker compose exec -T api python -m pos.adapters.cli analytics
docker compose exec -T api python -m pos.adapters.cli export > pos-results.csv
```

Команды `students`, `criteria` и `grades` поддерживают `add`, `list`, `get`, `update` и `delete`. Для оценок используются UUID студента и критерия из вывода первых двух групп. При выставлении или исправлении оценки можно добавить `--comment "Текст"`. Команда `result` принимает UUID студента, команда `results` показывает итоги по курсу.

## REST API

| Методы | Маршрут | Действие |
| --- | --- | --- |
| GET, POST | `/students` | Список и добавление студентов |
| GET, PUT, DELETE | `/students/{student_id}` | Просмотр, переименование и удаление студента |
| GET, POST | `/criteria` | Просмотр рубрикатора и добавление критерия |
| GET, PUT, DELETE | `/criteria/{criterion_id}` | Просмотр, изменение и удаление критерия |
| GET, POST | `/students/{student_id}/evaluations` | Список и выставление оценок |
| GET, PUT, DELETE | `/students/{student_id}/evaluations/{criterion_id}` | Просмотр, исправление и отмена оценки |
| GET | `/students/{student_id}/result` | Итог и список критериев без оценки |
| GET | `/results` | Итоги по всем студентам |
| GET | `/analytics` | Средние, количество выставленных оценок и пропусков |
| GET | `/exports/results.csv` | Выгрузка итогов в UTF-8 с BOM |

При создании критерия передайте `name`, `max_score` и `weight`, при выставлении оценки — `criterion_id`, `score` и, при необходимости, `comment`. В `PUT` для оценки достаточно нового `score`. Без поля `comment` предыдущий комментарий очищается. Баллы и веса принимаются числами или десятичными строками и возвращаются строками для сохранения точности.

Код `422` означает неверный ввод или балл вне диапазона, `404` — отсутствие записи, `409` — конфликт с текущими данными. Например, чтобы удалить студента или критерий, сначала нужно отменить связанные оценки.

Ошибки проверки формата запроса возвращают список с полями `loc`, `msg` и `type`. Числа `NaN` и `Infinity` отклоняются с кодом `422`.

## Правила расчёта

`Итог из 10 = 10 × Σ(балл / максимум × вес) / Σ(вес)`

- Максимум и вес строго положительны. Вес относительный, поэтому сумма весов может быть любой положительной. Для баллов, максимумов и весов поддерживается до шести знаков после запятой и значения до 999999.999999.
- Критерий без оценки даёт нулевой вклад, его вес входит в знаменатель. Поля `graded_count` и `missing_criterion_ids` отличают пропуск от выставленного нуля. При пустом рубрикаторе итог отсутствует.
- Расчёт использует точные дроби. Итог округляется один раз до сотых, половина округляется вверх.
- Аналитика усредняет итоговые баллы студентов. Среднее по критерию считается по выставленным оценкам, пропуски выводятся отдельно.

Например, при 8 из 10 с весом 40 и 15 из 20 с весом 60 итог равен `10 × (0.8 × 40 + 0.75 × 60) / 100 = 7.70`.

## Карта DDD

| Термин | Реализация и ответственность |
| --- | --- |
| Студент | Entity `Student` с UUID. Переименование сохраняет идентичность и оценки. |
| Критерий и рубрикатор | `Criterion` — Entity с UUID и правилами максимума и веса. `Rubric` — агрегат критериев для одного курса. Он гарантирует уникальность названий и проверяет принадлежность критерия. |
| Балл | Value Object `Score`. Два балла со значением 8.5 равны по значению. Объект неизменяемый, допускает только конечные неотрицательные числа. |
| Оценка | Entity `Evaluation` с ключом `(student_id, criterion_id)`. Она проверяет балл относительно критерия. Исправление сохраняет ключ и дату выставления. |
| Итог | Domain Service `ResultCalculator` получает студента, текущий рубрикатор и оценки. Итоги вычисляются при чтении и сразу учитывают исправления, отмены и изменение весов. |
| Хранение | `StudentRepository`, `RubricRepository` и `EvaluationRepository` заданы портами. Их адаптеры используют SQLAlchemy. Внешние ключи и составной ключ в SQLite защищают ссылки и уникальность оценки. |

Студент и оценка имеют собственный жизненный цикл. Изменения рубрикатора, затрагивающие оценки, проверяются в том же сценарии и транзакции. Максимум нельзя уменьшить ниже действующего балла. Параллельные записи сериализуются в SQLite через `BEGIN IMMEDIATE`.

## Архитектура и DI

Выбрана **Ports & Adapters**. Стрелки на схеме показывают зависимости кода.

```text
FastAPI и CLI ──► Application ──► Domain
SQLite ─────────► порты Application и модели Domain
CSV ────────────► модель итога Domain
```

| Папка или файл | Назначение |
| --- | --- |
| `pos/domain/` | Сущности, объекты-значения, инварианты и расчёт итога |
| `pos/application/services/` | Сервисы студентов, критериев, оценок и отчётов |
| `pos/adapters/api/router.py` и `pos/adapters/api/v1/` | Общий роутер и модули маршрутов |
| `pos/adapters/api/schemas/` | Pydantic-схемы запросов и ответов |
| `pos/adapters/cli/` | Консольные команды и вывод |
| `pos/adapters/sqlite/` | Репозитории и транзакции SQLite, ORM-модели в `models/` |
| `pos/adapters/csv_export.py` | Выгрузка в CSV |
| `pos/container.py` | Контейнер DI. Собирает Unit of Work, фабрику с часами UTC и сервисы. |
| `tests/` | Модульные проверки домена и интеграционные проверки API с SQLite |

FastAPI получает нужный сервис через `Depends`. CLI вызывает эти же сервисы из общего контейнера DI. Домен использует только стандартную библиотеку Python.

## GoF

| Группа | Паттерн | Зачем |
| --- | --- | --- |
| Порождающий | Фабрика `EvaluationFactory` | Создаёт или исправляет оценку по актуальному критерию. Обе операции используют одни правила для балла и комментария. |
| Структурный | Адаптер `SQLiteStudents` | Предоставляет интерфейс `StudentRepository` поверх сессии SQLAlchemy и преобразует строки таблицы в доменные объекты. |
| Поведенческий | Команда в `pos/adapters/cli/parser.py` | Каждая подкоманда привязывает действие, параметры и способ вывода в вызываемый обработчик. Консоль запускает обработчики одинаково, включая экспорт и демонстрацию. |

## Проверка

```sh
docker compose run --rm --build test
```

Тесты покрывают границы балла, отсутствующий критерий, взвешивание и округление, изменение результата при правке оценки и рубрикатора, аналитику, CSV, конкурентную запись и повторное открытие базы. Консольные тесты запускают CLI на временной SQLite-базе.

Контейнер `quality` запускает Ruff, mypy, Basedpyright и тесты с порогом покрытия 80%. Bandit и мутационные тесты домена можно запустить отдельно.

```sh
docker compose run --rm --build quality
docker compose run --rm quality bandit -q -r pos -ll
docker compose run --rm quality sh -ec 'mutmut run && mutmut results'
```

В Git-репозитории команда `pre-commit install` подключает проверку из `.pre-commit-config.yaml`. Хук запускает тот же контейнер `quality`.
